# Token 小精灵 macOS 正式发布、自动更新与防丢设计

## 目标

为 Token 小精灵建立可持续的 macOS 正式发布体系，并确保用户在小精灵不见时能立即找回。

本期只覆盖 macOS。Windows 和 Linux 继续保留现有构建能力，但不在本期接入正式签名和自动更新。

## 用户体验

### 正式发布与更新

- 版本号遵循 `主版本.功能版本.修复版本`，Git 标签使用 `v<版本号>`。
- 应用启动后延迟检查更新，运行期间定时复查；开发环境不联网检查。
- 检测到新版本后展示版本号和更新说明，由用户决定是否下载。
- 下载完成后提供“重启并更新”和“稍后”两个选择，不强制中断使用。
- 菜单栏提供“检查更新”，用户可随时主动检查。
- 更新失败只显示简短、可理解的提示，不影响桌宠继续运行。
- 首个带更新能力的正式版本仍需现有用户手动安装一次；以后版本可在应用内更新。
- LocalStorage 和应用用户数据目录不随覆盖安装或自动更新删除，成长数据必须保留。

### 菜单栏入口

应用在 macOS 菜单栏常驻一个小精灵图标，菜单包含：

1. 召回小精灵
2. 检查更新
3. 开机启动（可勾选）
4. 当前版本（只读）
5. 退出

“召回小精灵”会展开窗口、显示窗口、置于最前，并把它放到当前鼠标所在显示器的右下角安全区域。

### 自动防丢

应用在以下时机检查窗口是否仍在任意显示器的可见工作区内：

- 创建窗口后
- 显示器新增或移除
- 显示器尺寸或分辨率变化
- macOS 从睡眠恢复
- 用户从菜单栏召回
- 用户重复打开应用

如果窗口与所有显示器工作区完全没有可见交集，应用将其移回当前鼠标所在显示器右下角。若窗口仍有可操作区域可见，则尊重用户摆放，不主动移动。

应用使用单实例锁。再次打开应用只召回已有的小精灵，不创建第二个实例。

## 技术方案

### 主进程边界

`electron/main.js` 负责应用生命周期，但将新增能力拆成职责清晰的模块：

- 窗口定位模块：计算右下角位置、判断可见性、夹紧位置并执行召回。
- 菜单栏模块：创建 Tray 和菜单，将菜单动作回调给主进程。
- 更新模块：只在已打包的 macOS 应用中初始化更新器，统一处理检查、下载、安装和错误提示。

窗口定位的纯计算逻辑不依赖 Electron，方便单元测试。主进程只负责读取显示器和窗口状态、调用计算结果。

### 自动更新

- 使用 `electron-updater`，发布源为公开 GitHub Releases。
- Electron Builder 的 macOS 目标调整为 universal `dmg` 和 `zip`；ZIP 用于自动更新元数据生成。
- 构建配置声明 GitHub 发布源，构建时生成 `latest-mac.yml`、ZIP 和 DMG。
- 自动下载关闭，先征得用户同意；下载进度由更新模块维护，首期使用原生对话框反馈关键状态。
- 下载完成后调用安全退出并安装；用户选择稍后时保留已下载更新，下一次可再次提示。
- 更新器事件必须覆盖：发现更新、没有更新、下载完成、检查或下载失败。
- 启动自动检查延迟执行，避免拖慢桌宠首次出现；运行期间采用低频定时检查。

### 发布流水线

合并现有重复的 tag 构建职责，避免同一标签触发两套 macOS 发布：

1. `v*` 标签触发 macOS 发布任务。
2. 安装锁定依赖并运行全部测试。
3. 构建前校验 `package.json` 版本与标签一致。
4. 在 macOS Runner 上构建 universal DMG 和 ZIP。
5. 使用 Developer ID Application 证书签名，并提交 Apple 公证。
6. 创建 GitHub Release，上传安装包、更新包和更新元数据。

手动多平台构建仍可保留，但不得在 tag 事件中重复发布 macOS 资产。

### 签名与凭证

- 移除强制禁用签名的 `identity: null`。
- 启用 macOS hardened runtime，并配置必要的 entitlements。
- Apple 证书、公证密钥和密码只放在 GitHub Actions Secrets，不写入仓库、构建日志或客户端。
- 没有签名凭证时，本地仍可执行目录构建和测试，但不能声称已完成正式签名或公证。

## 异常与边界

- 无网络、GitHub 不可达或更新服务异常：不阻塞启动，仅在主动检查时向用户提示。
- 未打包开发环境：更新菜单显示为开发版本状态，不发起更新请求。
- Tray 图标创建失败：桌宠窗口仍正常运行，窗口内原有退出入口继续可用。
- 多显示器移除：只有窗口完全不可见时才自动迁移。
- 全屏工作区：沿用现有跨工作区和全屏可见设置；召回时显式显示并置顶。
- 更新安装前不迁移或重置存档；未来若数据结构变化，必须做向后兼容迁移。

## 测试与验收

### 自动测试

- 窗口完全在屏幕内时不移动。
- 窗口部分可见时不移动。
- 窗口完全在所有屏幕外时回到目标屏幕右下角。
- 支持负坐标和上下排列的多显示器。
- 收起窗口和展开窗口分别使用正确尺寸定位。
- 标签版本与应用版本不一致时发布流程失败。
- 全部既有 Vitest 测试继续通过。

### 构建验证

- 本地生产构建通过。
- 未签名的 macOS 目录构建可启动。
- Electron Builder 能生成 DMG、ZIP 和 `latest-mac.yml`。
- GitHub Actions 配置语法及所需 Secrets 名称有明确文档。

### 真机验收

- 菜单栏图标和五项菜单正确显示。
- 点击“召回小精灵”能从屏幕外、其他工作区或收起状态找回。
- 拔掉承载小精灵的外接显示器后，小精灵自动回到剩余屏幕。
- 重复打开应用不会创建第二只小精灵。
- 用一个测试 Release 验证发现更新、下载、稍后、重启安装全过程。
- 签名与公证结果通过 macOS 系统校验。

## 交付边界

本次代码交付包含发布配置、自动更新、菜单栏入口、自动防丢、测试和维护文档。

Apple Developer 会员购买、证书生成、Secrets 填写以及实际创建公开 Release 需要仓库所有者授权完成。未经明确许可，不执行正式发布。
